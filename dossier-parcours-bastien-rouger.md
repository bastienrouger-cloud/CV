## 8. Points sensibles — usage interne, ne pas publier

- **Le motif de l'interruption 2021-2023** est le refus du pass sanitaire. Rien sur
  le CV, rien sur le site. Pas par pudeur : c'est un marqueur politique, un
  recruteur sur deux se braque avant d'avoir lu la compétence, et ça n'a aucun
  rapport avec elle. La viticulture couvre la période sans mentir — formation
  suivie et emploi réel, tout est vérifiable.
  **Réponse préparée si la question vient en entretien :** « J'ai suspendu mon
  activité à cette période, j'ai repris en juin 2023 » — court, factuel, puis on
  enchaîne. Aucune obligation de développer.

- **Le risque « instabilité ».** Dix-huit établissements, c'est la force et le
  risque du profil. Trois éléments du CV disent l'inverse : le CDI à Montluçon, les
  deux ans en contrats directs au Millénaire, le CDD à la PIMAS. Phrase à préparer :
  la vacation était un choix pour la variété technique, et quand un établissement
  l'a voulu à demeure, il est resté deux ans. Ne pas soulever le sujet si personne
  ne le pose.

- **Coordonnées sur un site public — tranché, footer supprimé.** Aucune
  coordonnée en clair sur le site (ni téléphone ni mail affiché). Le footer a
  été retiré entièrement. Le RPPS est affiché dans le header (sous l'accroche

## 10. Système visuel

**Changement de palette (31 juillet 2026).** L'ancien vert + doré (« --nuit »
/ « --laiton ») faisait un contraste jugé trop violent. Nouvelle direction :
bleu profond quasi monochrome, avec le sable comme seule vraie touche chaude
(doré très discret, presque absent). Objectif inchangé : moderne, premium,
pas 100 % minimaliste, dans les codes du paramédical.

Variables CSS communes à `style.css` (site) et `cv-bastien-rouger-premium_1.html`
(CV imprimable) — mêmes noms, mêmes valeurs dans les deux fichiers, pour que les
deux documents se répondent. Noms de variables neutres (plus liés à une couleur
précise) pour survivre à un futur changement de palette.

```css
--fonce:        #13293D;  /* bleu marine profond : header, bandeau nav, capsule */
--fonce-clair:  #1F3E58;  /* variante claire pour les dégradés */
--accent:       #C9AD80;  /* sable/doré discret : titres de section, mise en avant */
--accent-clair: #E4D6BB;  /* accent clair : hover, prénom en emphase */
--clair:        #EDF2F5;  /* texte clair sur fond sombre */
--clair-sourd:  #9FB4C4;  /* texte clair secondaire sur fond sombre */
--papier:       #FCFAF7;  /* fond de page, crème très clair (inchangé) */
--encre:        #1B2430;  /* texte principal, bleu-noir */
--sourd:        #64707A;  /* texte secondaire */
--filet:        #DEE3E6;  /* filets et bordures */
```

Les ombres (`box-shadow`) et gradients codés en dur ont été recalés sur ces
teintes (ex. `rgba(19,41,61,…)` = `--fonce` en rgb, `rgba(201,173,128,…)` =
`--accent` en rgb). Sur le CV imprimable, le mode « encre légère » (bascule
écran) utilise un brun-sable `#8C6B3D` à la place de l'accent pour rester
lisible sur fond clair.

**QR code vers le site (1er août 2026).** Ajouté dans la colonne sombre du CV
imprimable, juste sous le bloc Contact — bloc `.qr-bloc`, lien
`https://bastienrouger-cloud.github.io/CV/`. Détails techniques :
- QR généré en local (lib Python `qrcode`, SVG vectoriel intégré inline dans
  le HTML — pas d'image externe, pas de dépendance réseau à l'ouverture).
  Modules en `#13293D` sur fond blanc plein (carte blanche dédiée), pour un
  contraste de scan maximal — le bleu foncé est aussi lisible qu'un noir pur
  pour un lecteur de QR.
- Toute la carte (QR + légende « Le site / Cliquable ici · scannable au
  téléphone ») est un unique `<a href="...">`. Objectif double : le
  téléphone scanne le QR sur le papier, ET le lien reste cliquable une fois
  le CV exporté en PDF (Chrome conserve les `<a href>` de la page comme
  liens cliquables dans le PDF généré via *Enregistrer en PDF* à
  l'impression — c'est le mécanisme utilisé ici plutôt qu'une solution
  d'annotation PDF séparée).
- Régénérer le SVG si l'URL change un jour : script Python avec
  `qrcode.image.svg.SvgPathImage`, voir historique de session pour la
  commande exacte.
- Légende retouchée le 1er août 2026, puis re-corrigée le même jour après
  relecture critique : « CV complet » sous-entendait que le papier tenu en
  main est une version incomplète — dévalorise le document au moment où il
  est lu. Et « Cliquable ici » est faux sur papier (un QR se scanne, il ne
  se clique pas). Version finale, qui annonce le bénéfice concret plutôt que
  le manque, et qui reste vraie sur les deux supports :
  **« Les 18 établissements, service par service »** /
  *« À scanner — cliquable à l'écran »* (scanner en premier, le clic
  qualifié « à l'écran » pour ne pas mentir sur le papier tout en gardant
  l'indication utile pour la lecture PDF — cliquer sur un QR n'est pas encore
  un réflexe naturel, contrairement au scan).
- Taille réduite le 1er août 2026 : fonctionnait comme CTA mais jugé trop
  imposant/pas assez sobre pour le reste de la colonne (seul bloc encadré du
  flanc). QR ramené de 15mm à 12,5mm (encore confortable à scanner tenu en
  main), padding et police du texte resserrés (`.qr-texte` 6.8pt→5.9pt,
  `.qr-texte b` 7.6pt→6.5pt). Toujours 1 page.

**Typographie**
- Titres, nom, accroche, chiffres : `Georgia, "Iowan Old Style", "Times New Roman", serif`
- Corps : `"Segoe UI", -apple-system, BlinkMacSystemFont, Roboto, Helvetica, Arial, sans-serif`
- Le mélange serif / sans donne la chaleur sans sacrifier la lisibilité rapide.

**Principes de mise en page**
- Une seule forme expressive (la capsule / le panneau « Terrains d'exercice »).
  Tout le reste sobre, pour qu'elle porte seule.
- Colonne latérale teintée pleine hauteur (CV) / bandeau sombre (site), reste
  du contenu sur papier crème.
- Rail chronologique à gauche du parcours : les dates alignées en colonne, pour que
  les chevauchements se lisent d'un coup d'œil.
- Variable `--echelle` en tête du CSS du CV (8.3pt) : seul levier à toucher pour
  faire tenir la page A4.

## 11. Plan du site

Deux dépôts séparés, aucun mélange avec Humming Cob.

- **`/` — page unique, tranché.** Plus de page `/parcours` séparée : tout le
  détail (chronologie complète, 18 établissements, 5 cabinets) reste sur `index.html`,
  dans les menus déroulants (`<details>`) déjà en place. Même contenu, même
  palette, responsive.
- **Navigation — pas de footer.** Header : identité + métier + RPPS uniquement.
  Juste en dessous, un bandeau `.bandeau-nav` (nav + bouton contact) en
  `position:sticky` : il reste à sa place initiale puis se colle en haut au
  scroll. En mobile (<680px), le bouton contact disparaît du bandeau et devient
  une barre fixe (`.contact-mobile`) collée en bas de l'écran, toujours visible.
  Footer entièrement supprimé (plus de téléphone/mail en clair nulle part sur
  le site, cf. section 8).
- **`/web`** — plus tard : Humming Cob, l'outil de compatibilité génétique
  (coefficient de consanguinité Wright/Henderson), le client vétérinaire, VK Studio.

**Photo** — pas sur le CV (pas de place verticale, et inutile pour les agences
d'intérim). Sur le site, oui : un titulaire qui choisit son remplaçant confie ses
patients à quelqu'un, un visage aide. Photo neutre, en extérieur, sans blouse.

**Attente réaliste** — sur dix recruteurs infirmiers en Creuse, un ou deux
cliqueront. La vraie valeur du site est ailleurs : les agences d'intérim regardent,
et c'est le socle du futur portfolio web.
